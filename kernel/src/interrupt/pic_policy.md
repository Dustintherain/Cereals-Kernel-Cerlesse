# 中断控制器选型策略（v0.4，使用 PIC 第一版）

## 决策
- v0.4 第一版使用 **PIC（8259A）**。
- 原因不是“PIC 更先进”，而是**先让外设中断具有最小可验证的分发路径**。
- 本内核当前的编译链路、QEMU 配置、测试断言都更适合先在 PIC 上跑通 IRQ 语义。

## 选型依据
- PIC 的初始化序列和端口语义在文档与实例方面更少歧义，适合先做“可接通”的版本。
- APIC（LAPIC/IOAPIC/redirection）在同一套目标上也可以做，但语义更复杂，更适合在 PIC 路径确立后迁移。
- 当前先固定“master/slave + IRQ0..15 → 向量 32..47”的常见映射，后续可通过映射函数与控制器枚举切换进行扩展。

## 当前实现范围
- `ControllerKind::Pic`：启用初始化、mask 位图、enable/disable、带向量的 EOI。
- `ControllerKind::Apic`：尚未实现，目前仅保留枚举与 no-op 语义占位。
- PIC 端口直接内联在 `controller.rs` 中，不依赖串口驱动。

## 剩余工作
- 外设中断入口将中断向量交给控制器做 EOI。
- 在此之上接 Timer/PIT 与键盘 PS/2，再验证 tick 与按键回显。
- 后续再考虑迁移到 APIC 或提供可配置策略，而不是一开始就同时实现两条路线。
