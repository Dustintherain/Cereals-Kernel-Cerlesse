# 内核架构（第一阶段）

- 阶段：第一阶段 / 架构确定
- 最后更新：2026-10-06
- 状态：**已确定方向，后续开发中会反复修订**

## 1. 项目定位

使用 **Rust 从零开发一个类 Linux 的高性能系统内核**（代号 Cerlesse）：

- 不做"完整 Linux 替代品"，而是按 **Boot → 内存 → 中断 → 进程 → 调度 → 系统调用 → 文件系统 → 驱动 → 用户态 → Shell → 网络** 逐层构建。
- 首个架构决策：**Monolithic Kernel（宏内核）+ Rust**。
- 跨平台策略：内核目标平台为 **x86_64**（QEMU 验证优先），开发主机同时支持 **Linux 与 Windows**（交叉编译 + QEMU）。

## 2. 语言分工（Rust + Python + Go）

| 语言 | 职责 | 说明 |
| ---- | ---- | ---- |
| **Rust** | 内核核心、用户态关键程序、libc 替代层 | `no_std` 环境，核心内容全部用 Rust 编写，保证内存安全与性能 |
| **Python** | 构建脚本、磁盘镜像制作、测试框架、代码生成 | 运行在开发主机上，不进入内核；负责 mkfs 镜像组装、集成测试驱动、QEMU 自动化 |
| **Go** | 主机侧工具链与服务 | 镜像构建服务、测试编排服务、串口日志收集/分析工具等高并发主机工具 |

> 原则：**任何进入内核运行时的代码都必须是 Rust**；Python/Go 只出现在开发主机（host）侧。

## 4. 第一版（v1.0 以内）目标

第一版只需要做到：

```text
启动 → 进入 Rust Kernel → 初始化内存 → 初始化中断 → 初始化时钟
     → 创建第一个任务 → 切换任务 → 系统调用 → 加载用户程序 → Shell
```

做到这里就拥有了一个真正意义上的"小型操作系统内核"。

## 5. 第一版明确不做（非目标）

- SMP 多核（v1.0 之后）
- USB / Wi-Fi / GPU
- 完整 POSIX 兼容
- 完整 ELF 动态链接
- 完整 TCP/IP 栈（第一版只做基础网络或留到 v0.9 简化实现）
- 多架构支持（只做 x86_64）

## 6. 关键设计决策记录（ADR）

| 编号 | 决策 | 理由 | 状态 |
| ---- | ---- | ---- | ---- |
| ADR-001 | 宏内核而非微内核 | 第一版复杂度最低，最贴近类 Linux 学习目标 | 已确定 |
| ADR-002 | 优先 UEFI + x86_64 + QEMU | 避开真实硬件兼容性泥潭，迭代最快 | 已确定 |
| ADR-003 | 内核核心只用 Rust；Python/Go 仅限主机侧 | 满足"Rust 编写核心内容"的要求 | 已确定 |
| ADR-004 | 先 RAMFS 后磁盘 FS；VFS 抽象优先 | 避免把具体文件系统写死进内核 | 已确定 |
| ADR-005 | 调度器第一版 Round Robin | 最简单、最容易验证正确性 | 已确定 |
| ADR-006 | bootloader→内核跳转显式 `extern "sysv64"` | uefi 目标的 `extern "C"` 是 Win64 ABI（RCX），内核期望 SysV（RDI） | v0.1 已实施 |
| ADR-007 | 内核固定链接地址 32MiB | 实测 OVMF 把 0x900000–0x1500000 占为 BootServicesData；32MiB 落在空闲常规内存 | v0.1 已实施 |
| ADR-008 | 内核强制静态非 PIE 链接（`relocation-model=static`） | 目标默认 PIE，绝对数据靠 `.rela.dyn` 加载时重定位，bootloader 不处理 → v0.2 实测 IDT handler 地址错误；固定装载地址下静态链接最简且无此风险 | v0.2 已实施 |

> 后续每做出新的重大决策，在此表追加 ADR 编号并同步 [../DEVELOPMENT.md](../DEVELOPMENT.md)。
