## 1. 概述

v0.6 与 v0.7 一起构成系统调用 / 用户空间阶段，但两者有清晰先后：

1. **v0.6 核心**：建立用户态 / 内核态隔离 + 系统调用入口 + 第一批 syscall + 用户态 `hello` 运行。
2. **v0.7 扩展**：VFS 对接 syscall 的文件语义（open/read/write/close）、ELF Loader 完整化（User Stack/Heap）、用户程序与 Shell 的初步加载能力。

依赖顺序（粗粒度）：

- 高半区映射与用户地址空间隔离（内核 `0xFFFF...` / 用户 `0x0000...`）是 v0.6 的基础，必须先于 syscall 的用户态隔离验证。
- ELF Loader 依赖内存映射能力（已在 v0.3 拿到）与用户栈 / 用户堆语义，因此放在 v0.7 再完整化。
- 文件描述符表与 VFS 对接在 v0.7 与 filesystem.md 一起完成。

## 2. v0.6（Syscall 入口 + 用户态隔离 + 第一批 syscall）

### 2.1 用户态/内核态隔离（ADR-009 延续）

- v0.3 内核延续恒等映射（phys == virt），高半区映射推迟到本阶段。
- 本阶段目标：在页表层区分内核与用户地址空间，使得用户程序运行在隔离的低地址空间，内核保留在高地址空间。
- 实现顺序（建议）：页表构建策略调整 → 内核高半区重定位语义 → 用户地址空间映射 → 切换地址空间的入口与返回语义 → syscall 入口与返回。
- 验收依赖：必须先在串口可观察到用户态入口/返回语义，再谈文件/进程语义。

### 2.2 系统调用入口（可直接开工的草案）

#### 2.2.1 入口策略草案

- 优先候选：**`syscall` / `sysret`**。
  - 理由：快速用户态/内核态切换，不走中断门，适合第一版 syscall 热点路径。
- 备选：**`int 0x80` 风格入口**。
  - 理由：语义更传统、容易在调试时观测栈帧与向量行为。
- 最终选型在编码时再写成决策记录（寄存器约定、错误返回方式、是否复用现有中断帧格式）。

#### 2.2.2 寄存器约定草案（x86_64）

- syscall 编号走一个固定寄存器（例如 `rax`），参数走通用寄存器（例如 `rdi/rsi/rdx/r10/r8/r9` 风格，编码时再确定具体顺序）。
- 返回值走 `rax`。
- 错误返回方式在实现时定，比如：
  - 成功返回结果值
  - 失败返回负错误码
  - 或返回错误标记 + 分开读取 errno 风格
- 不绑死具体值，编码前再把约定表固化。

#### 2.2.3 系统调用分发层草案

- 分发层目标：把用户请求路由到各子系统实现。
- v0.6 先实现**最小分发表**，v0.7 再扩展。
- 分发表至少包含：syscall 编号 → 实现函数指针（或内部路由枚举）。
- 未实现/保留号码的处理策略在实现时定（例如返回未实现错误）。

### 2.3 第一批系统调用（计划，已可直接转成任务项）

| syscall | 计划版本 | 说明 |
| ---- | ---- | ---- |
| `exit`   | v0.6     | 终止用户进程，回收退出码 |
| `write`  | v0.6     | 输出（串口 / 控制台 / VFS 视对接阶段） |
| `read`   | v0.6/v0.7 | 输入（控制台 / 文件视对接阶段） |
| `open`   | v0.7     | VFS 对接后再完整化 |
| `close`  | v0.7     | VFS 对接后再完整化 |
| `fork`   | v0.6（基础）/v0.7（完善） | 进程复制语义 |
| `exec`   | v0.6/v0.7 | ELF Loader 加载新程序 |
| `wait`   | v0.6/v0.7 | 子进程退出回收 |

### 2.4 最小 libc / 系统调用封装（`libc/`）

- 用户态程序通过 `libc/` 封装调用 syscall，而不是直接写入口指令。
- `libc/` 至少提供：最小基础类型支持、`start` → `main` 启动胶水、对 `exit/write/read` 等的封装。
- 用户态目标是 `no_std` 用户态程序，产出静态 ELF（workspace 规划已约定 `user/*` 在 v0.6 起加入）。
- v0.6 核心封装目标：至少让用户态程序能通过 `libc` 调用 `exit` / `write` 等初步 syscall。

### 2.5 验收（v0.6）

- [ ] 用户态 `hello` 程序通过 ELF Loader 加载并运行
- [ ] 用户态隔离下 syscall 入口/返回可观察
- [ ] `exit` 能回收退出码（至少在串口可观察到）
- [ ] `fork`/`exec`/`wait` 基本流程可用（v0.7 完善前，v0.6 至少具备可验证骨架）
- [ ] `getpid`/`sleep` 可用

## 3. v0.7（ELF Loader 完整化 + VFS/syscall 对接）

### 3.1 ELF Loader、User Stack、User Heap

- ELF Loader 要能加载用户程序的 PT_LOAD 段到用户地址空间，并准备用户栈/用户堆语义。
- 用户栈/用户堆的建立与前述高半区/用户地址空间隔离语义一致。
- ELF Loader 完整化后，才能加载除最小 `hello` 之外的更多用户程序。

### 3.2 文件语义对接

- `open`/`read`/`write`/`close` 在 v0.7 与 VFS 对接（见 docs/filesystem.md）。
- 文件描述符表在进程模型基础上建立，并通过 syscall 层暴露给用户态。

### 3.3 验收（v0.7）

- [ ] 用户态 `hello` 之外的基础用户程序可加载
- [ ] 文件描述符语义可用（至少串口/控制台设备层面先行）
- [ ] `ls`/`cat`/`cd` 等操作最终能在 RAMFS 上生效（前提是 VFS/RAMFS 已就位，见 filesystem.md）

## 4. 调用链示例

调用链示例（按规划记录，实际实现顺序以代码为准）：

1. 用户态 `write()` → libc 封装 → syscall 入口
2. 内核 `sys_write` → VFS → 设备/文件后端
3. 后端可以是串口/控制台，也可以是后续的磁盘文件系统

本示例用意是说明 syscall 层不应把具体后端写死；VFS 抽象优先（ADR-004）。

## 5. 非目标 / 后续

- 完整 ELF 动态链接：非第一版目标。
- 完整 POSIX：非第一版目标。
- 完整内存保护细节（例如高半区重定位期间的暂态语义、页表切换时的临界处理）：在实现时记录，必要时追加 ADR。
- 高半区映射本身延续 ADR-009 中“与用户态隔离一并完成”的计划，不要在 v0.6 之前单独做高半区搬迁。
